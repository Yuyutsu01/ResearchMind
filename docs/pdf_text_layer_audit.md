# ResearchMind PDF.js Text Layer Audit Report

## Executive Summary

A comprehensive 10-point audit was performed on ResearchMind's PDF rendering and text selection pipeline to diagnose why native browser text selection experienced fragmentation compared to Mozilla's official PDF.js viewer and Adobe Acrobat.

**Key Finding**: Text selection fragmentation is **NOT** caused by PDF.js text layer generation logic. It is caused by **missing official PDF.js `pdf_viewer.css` styles**, **unhandled CSS resets from Tailwind CSS**, **missing CSS custom property variables (`--scale-factor`)**, and **DOM node destruction during React state reconciliation**.

---

## Audit Findings (10-Point Analysis)

### 1. Official PDF.js TextLayer CSS Verification
* **Status**: ❌ **MISSING**.
* **Finding**: `pdf_viewer.css` (defining `.textLayer`, `.textLayer span`, `.textLayer ::selection`, `--scale-factor`, and `white-space: pre;`) was not imported in `layout.tsx` or `globals.css`.
* **Root Cause Impact**: `.textLayer span` elements rendered without essential font metrics positioning, causing line rects to fragment visually.

### 2. CSS Framework Overrides & Resets (Tailwind CSS)
* **Status**: ⚠️ **CONFLICT DETECTED**.
* **Finding**: Tailwind CSS `@import "tailwindcss";` and `globals.css` apply global `font-family: 'Outfit', sans-serif;` and CSS resets (`line-height`, `box-sizing`, `vertical-align`).
* **Root Cause Impact**: When text spans inherit the custom web font (`Outfit`) instead of standard monospace/sans-serif font metrics computed by PDF.js, character bounding boxes expand or shrink horizontally. This misaligns HTML text spans with canvas text rendering, breaking continuous multi-word text highlighting into fragmented boxes.

### 3. `renderTextLayer()` API Parameters & Custom CSS Variables
* **Status**: ⚠️ **SUB-OPTIMAL CONFIGURATION**.
* **Finding**: `renderTextLayer()` was invoked without setting `--scale-factor` on the `.textLayer` container div element and without passing `enhanceTextSelection: true`.
* **Root Cause Impact**: PDF.js relies on `--scale-factor` CSS variable to scale font sizes and character spacing (`letter-spacing`, `transform: scaleX(...)`). Without this variable, spans fallback to default browser 16px font sizes before CSS transforms are applied.

### 4. Generated DOM Structure Inspection
* **Status**: ✅ **CLEAN CONTAINER (NO UNEXPECTED WRAPPERS)**.
* **Finding**: No custom React fragments, portals, or wrapper divs exist inside `.textLayer`. Only spans generated by PDF.js are mounted.

### 5. CSS Transforms & Pixel Ratio Alignment
* **Status**: ⚠️ **TRANSFORM ORIGIN & fractional RESOLUTION MISMATCH**.
* **Finding**: Canvas uses retina device pixel ratio (`canvas.width = viewport.width * dpr`), whereas `.textLayer` relies on raw CSS pixels.
* **Root Cause Impact**: Sub-pixel fractional viewport widths (e.g. `789.4px`) without `transform-origin: 0 0;` cause 0.5px rounding shifts between canvas characters and text layer DOM spans.

### 6. React Reconciliation & DOM Stability During Scroll
* **Status**: ⚠️ **DOM NODE WIPING ON RE-RENDER**.
* **Finding**: In `ReadingWorkspace.tsx`, `renderPage()` executes `textLayerDiv.innerHTML = ""` whenever `isVisible` or `scale` updates during scrolling.
* **Root Cause Impact**: Wiping `innerHTML` during scrolling destroys DOM node references held by active browser text selections (`window.getSelection()`), causing selection ranges to collapse or clear unexpectedly.

### 7. Selection Behavior & Selection API
* **Status**: ✅ **NATIVE SELECTION ACTIVE**.
* **Finding**: Selection uses standard `window.getSelection()` without manual highlight overlays.
* **Root Cause Impact**: Highlighting fragmentation is purely visual due to missing `pdf_viewer.css` `::selection` rules.

### 8. Manual Highlight Backgrounds
* **Status**: ✅ **NO MANUAL OVERLAYS**.
* **Finding**: No custom canvas highlights or manual background spans are injected.

### 9. Comparison Against Mozilla's Official PDF.js Viewer

| Architectural Feature | Mozilla PDF.js Official Viewer | ResearchMind Previous Implementation |
| :--- | :--- | :--- |
| **Stylesheets** | `pdf_viewer.css` imported | ❌ Missing |
| **CSS Variables** | `--scale-factor` assigned to container | ❌ Missing |
| **CSS Resets** | Isolated `.textLayer span` resets | ⚠️ Tailwind global font inheritance |
| **Selection Highlight** | `.textLayer ::selection { background: blue; }` | ⚠️ Default browser selection |
| **DOM Stability** | Stable nodes cached per page | ⚠️ Wiped on scroll re-renders |

## 10. Root Cause Summary & Recommended Fix Strategy

### Root Causes Identified:
1. **Missing `pdf_viewer.css`**: Spans lacked official PDF.js positioning, `color: transparent;`, and `::selection` rules.
2. **Tailwind CSS Font & Line-Height Inheritance**: `Outfit` font override corrupted character bounding box math computed by PDF.js.
3. **Missing `--scale-factor` CSS Variable**: Prevented exact character scaling.
4. **`innerHTML` Destruction on Scroll**: Active selections were cleared when virtualized pages re-rendered.

### Proposed Fix Strategy (Prepared for Next Steps):
1. Import `pdf_viewer.css` (`https://cdnjs.cloudflare.com/ajax/libs/pdf.js/3.4.120/pdf_viewer.min.css`) in `layout.tsx`.
2. Add explicit CSS isolation for `.textLayer` in `globals.css`:
   ```css
   .textLayer {
     position: absolute;
     text-align: initial;
     left: 0; top: 0; right: 0; bottom: 0;
     overflow: hidden;
     opacity: 0.25;
     line-height: 1.0;
     user-select: text;
   }
   .textLayer span {
     color: transparent;
     position: absolute;
     white-space: pre;
     cursor: text;
     transform-origin: 0% 0%;
     font-family: sans-serif !important;
   }
   .textLayer ::selection {
     background: rgba(0, 102, 255, 0.35);
     color: transparent;
   }
   ```
3. Assign `--scale-factor: ${scale}` to `textLayerDiv.style.setProperty("--scale-factor", scale.toString())`.
4. Wrap text layer rendering in a render-lock guard so active text layer DOM nodes are NOT wiped while text selection is active.
